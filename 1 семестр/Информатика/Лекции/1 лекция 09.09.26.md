# Начала теории вероятности

> **Исход** — это конкретный (элементарный) результат случайного эксперимента 
> **Событие** — то подмножество всех возможных исходов случайного эксперимента 

Событие считается **произошедшим**, если исход эксперимента принадлежит множеству исходов события.

**Вероятность события** — отношение числа благоприятных исходов (составляющих событие) к числу всех исходов. $p=\dfrac{m}{n}$, где $m$ — благоприятные исходы, $n$ — все исходы.
*Однако, эти рассуждения работают только в случае равновероятных исходов*

$p \in [0,1]$

**Достоверное** событие состоит из всех исходов, $p=1$
**Невозможное** событие составляет пустое множество исходов, $p=0$

### Несчетные множества исходов
Когда множество исходов несчетно пересчитать их всех невозможно. 

#### $\sigma$-алгебра
Это алгебра пространства исходов.
В ней задают вероятностную меру
Например, для отрезка $[0;1]$ можно использовать меру Лебега (длина отрезка).

Но в базовом курсе информатики мы работаем только с конечными множествами (а, следовательно, и счетных множеств) исходов.

### События

#### Определения
> **Пространство исходов** — все возможные исходы эксперимента

> Несколько событий называются **несовместными**, если никакие два из них не могут появиться одновременно.
> **Полная группа событий** — набор несовместных событий, объединение исходов которых составляет все пространство исходов

> **Совместные события**, обязательно содержат общие исходы

#### Алгебра событий
- $P(A) + P(\lnot A) = 1$    ($P(\lnot A) = 1 - P(A)$) — сумма противоположных
- $P(A \cup B) = P(A)+P(B)$ — сумма несовместных
- $P(A \cup B) = P(A) + P(B) - P(A \cap B)$ — сумма совместных
- $P(A \cup B \cup C)$ — формула включений-исключений (для совместных)
*Это продолжение последней формулы*
$=P(A\cup B) + P(C) - P((A \cup B) \cap C) =P(A) + P(B) +P(C) - P(A \cap B) - P(A \cap C) - P(A \cap C) + P(A \cap B \cap C)$

# Теория информации

### Равновероятные события

Посмотрим на эксперимент с несколькими бросками честной монетки. Тогда всего исходов может быть $2^n$, где $n$ — количество бросков монетки. Представим, что есть наблюдатель, который сообщает о результатах эксперимента. Тогда каждый исход этого эксперимента можно закодировать с помощью $n$ нулей и единиц, обозначив одну сторону монеты нулем, другую единицей (информационный бит).

В случайных экспериментах с равными вероятностями исходов работает формула Хартли по вычислению количества бит информации для кодирования исхода:
$$\begin{array}{rl}
H=\log_{2}N & N = 2^H
\end{array}$$
где $N$ — количество исходов.

Причем $N$ может быть и не степенью двойки. Кажется логичным, что количество информационных битов может быть только целым, но это не так, потому что эти биты не компьютерные, а *информационные*. Это **мера информации**. 

*Теоретически можно придумать другие биты, у которых 3 состояния, тогда в формуле основание степени меняется на 3, но это не прижилось*

Если же мы хотим записать эти исходы в компьютере, то нам придется округлить количество бит информации вверх.

**Важно**, что это работает только для равновероятных исходов

### Неравномерное распределение

Возьмем 4 исхода: вероятность первого $\dfrac{1}{2}$, второго — $\dfrac{1}{4}$, третьего и четвертого — $\dfrac{1}{8}$.
Тогда самые вероятные источники несут меньше всего информации. А самые редкие — больше всего. 

Чтобы определить количество информации для неравномерного распределения используют формулу энтропии Шеннона.

> **Энтропия** — мера неопределенности источника

Энтропия $H(A)$ показывает среднее число бит в сообщении источника $A$ с неравномерно распределенными вероятностями исходов $P_{i}$

> Частная энтропия $H_{i}(A)$ показывает количество переданной информации в случае $i$-ого исхода.

$H_{i}(A)=-\log_{2}P_{i}$ — частная энтропия
$H(A) = \sum_\limits{i=0}^\limits{m} P_{i}\times H_{i}(A)= - \sum_\limits{i=0}^\limits{m} P_{i}\times \log_{2}P_{i}$ — энтропия
> Максимум энтропии достигается при равной вероятности исходов эксперимента


#### Пример
Возьмем те исходы, упомянутые выше.
Тогда, подставив числа в формулу: $H(A) = -(-\dfrac{1}{2}-\dfrac{2}{4}-\dfrac{3}{8}-\dfrac{3}{8})=\dfrac{1}{2}+\dfrac{1}{2}+\dfrac{3}{4}=1+\dfrac{3}{4}=\dfrac{7}{4} \text{бита}$
Если мы будем считать по формуле Хартли, то у нас выйдет 2 бита.

*Так получилось из-за того, что по сути $H_{i}(A)$ показывает идеальное количество битов для кодирования этой информации (не всегда это возможно)*

![[Drawing 2026-09-11 00.38.25.excalidraw]]
Тогда для кодирования исхода с вероятностью $\dfrac{1}{2}$ мы можем использовать код "0", с вероятностью $\dfrac{1}{4}$ — "10", исходы с вероятностью $\dfrac{1}{8}$ — "110" и "111"

Причем для однозначного декодирования код должен удовлетворять условию Фано. (Выше как раз пример этого).

На самом деле, классический алгоритм Хаффмана (формирование как раз подобного дерева для кодирования информации) далеко не во всех случаях позволяет минимизировать число бит в сообщении (почему?). 


### Естественный язык
Текст на любом естественном языке содержит определенные закономерности и правила.

Чтобы учесть эти закономерности, энтропию языка принято считать как предел.

Энтропия языка не превышает $1.5$ бита информации. При этом каждая буква требует 5 битов для представления в компьютере. Поэтому естественный язык имеет высокую степень избыточности.

$H_{L}=\lim_{ n \to \infty } \dfrac{H(P^n)}{n}$ — энтропия английского языка

### Хранение информации в памяти компьютера
Любые данные (числа, символы, графические и звуковые образы) в компьютере представляются в виде последовательностей из нулей и единиц.

#### Целые числа
Для представления целых $2^k$ чисел **без знака** можно использовать битовую последовательность длины $k$.
С такими последовательностями можно совершать основные арифметические действия.

Для представления целых чисел **со знаком** используются три представления числа: 
- **Прямой код** — его модуль и знак числа (единица в старшем разряде)
	Такие числа (отрицательные) нельзя использовать для арифметических операций.
- **Обратный код для отрицательного числа** — инвертированная битовая строка прямого кода этого числа (старший бит не меняется!)
	Их можно складывать как обычные (беззнаковые числа), но надо прибавить старший бит к младшему, а старший бит затираем
- **Дополнительный код** — обратный код с прибавлением единицы к младшему разряду. Он просто упрощает жизнь вычислительным машинам (компьютерам).
	Для сложения чисел нужно складывать как обычные, просто затирая старший бит.

Алгоритм сложения для беззнаковых можно переиспользовать для работы с числами в дополнительном коде.
